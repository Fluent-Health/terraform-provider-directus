# Directus Provider

A Terraform provider for [Directus](https://directus.io). It manages instance
*configuration*: the things an administrator otherwise clicks together in the
Data Studio. It does not manage content items.

Tested against Directus 12.4.

## Authentication

The provider authenticates with a user's **static token** (the user's `token`
field, under User Directory → user → Token). Use an **admin** user: Directus
filters some configuration out of non-admin reads, and the provider would
treat a hidden object as deleted.

## Behaviour

- **Reads are batched.** Each kind of object is listed once per Terraform run
  and shared by every resource of that kind, instead of one request per
  resource.
- **Missing objects.** Directus answers `403 FORBIDDEN` (not 404) for an item
  that does not exist. The provider decides an object is gone only when a
  successful listing does not contain it, so a permission problem surfaces as
  an error instead of a plan to recreate everything.
- **Retries.** HTTP 429, 502, 503 and 504 are retried with exponential backoff,
  honouring `Retry-After`.

## Example Usage

```terraform
terraform {
  required_providers {
    directus = {
      source  = "Fluent-Health/directus"
      version = "~> 0.1"
    }
  }
}

# The token is a Directus user's static token. Use an admin user: Directus
# hides some configuration (e.g. flows folders) from non-admin users.
# Or set DIRECTUS_URL and DIRECTUS_TOKEN in the environment.
provider "directus" {
  url   = "https://cms.example.com"
  token = var.directus_token
}

variable "directus_token" {
  type      = string
  sensitive = true
}
```
